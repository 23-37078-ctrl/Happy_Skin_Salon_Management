# Synthetic transaction dataset

## Purpose and scope

`transactions_3_years_synthetic.csv` is a generated sample dataset for demonstrating and evaluating the synthetic forecasting workflow. It is **not** a record of Happy Skin Salon's actual customers, staff, appointments, payments, or revenue. Do not use it for accounting, payroll, business decisions, or claims about actual salon performance.

The file contains 20,949 generated transaction rows dated from 2023-10-21 through 2026-10-30. Every row is marked `SYNTHETIC_SAMPLE_NOT_REAL_TRANSACTION`. It currently covers three illustrative branches and 53 services. The generator uses a fixed random seed, so rerunning it with the same code reproduces the file.

## File format

- Encoding: UTF-8 with BOM
- Delimiter: comma
- One row per synthetic transaction
- Datetimes: local-looking wall-clock values in `YYYY-MM-DD HH:MM:SS`; no timezone is stored
- Currency: Philippine pesos (PHP)
- Monetary and rate values: decimal strings with two fractional digits

## Columns

| Column | Meaning | Notes |
| --- | --- | --- |
| `transaction_id` | Synthetic transaction identifier | `SYN-TXN-` plus a zero-padded sequence |
| `booking_id` | Synthetic related booking identifier | `SYN-BOOK-` plus a zero-padded sequence; not a real booking reference |
| `transaction_datetime` | Generated transaction date and time | Naive datetime; do not interpret as UTC |
| `branch_name` | Illustrative branch label | Three generated branch names |
| `client_name` | Synthetic customer label | Sequential placeholder, not a person |
| `service_name` | Service label | Selected from the generator's service list |
| `service_provider` | Synthetic provider label | Placeholder numbered 01–12 |
| `encoded_by` | Synthetic staff label | Placeholder numbered 01–09 |
| `payment_method` | Generated payment category | Cash, GCash, Maya, or Card |
| `subtotal_php` | Generated pre-discount amount | Based on the generator's current service prices, not historical prices |
| `discount_php` | Generated discount amount | Typically 0%, 5%, or 10% of subtotal |
| `sale_php` | Generated amount after discount | `subtotal_php - discount_php` |
| `commission_rate_percent` | Generated commission rate | One of 0%, 5%, 8%, or 10% |
| `commission_php` | Generated commission amount | `sale_php * commission_rate_percent / 100`, rounded to two decimals |
| `status` | Synthetic transaction status | All rows currently say `Completed` |
| `data_origin` | Data provenance marker | Must remain `SYNTHETIC_SAMPLE_NOT_REAL_TRANSACTION` |

## Generation and validation

The dataset is generated by [`../scripts/generate_transaction_csv.py`](../scripts/generate_transaction_csv.py). It samples dates across the configured three-year range and draws branches, services, times, discounts, commission rates, and payment methods from fixed lists and weights. The generator comments document the price source and explain that verified historical prices were unavailable.

The importer/validator is [`../scripts/import_synthetic_transactions_csv.py`](../scripts/import_synthetic_transactions_csv.py). It checks the required columns, provenance marker, completed status, recognized branches/services, unique transaction IDs, date and amount validity, and boundary dates. It aggregates daily service-level transaction counts and revenue for the synthetic forecasting tables.

Validate without writing to the database (from `backend`):

```powershell
python scripts\import_synthetic_transactions_csv.py
```

By default the importer performs a dry run. Passing `--import` stages the data into isolated `synthetic_*` tables; it does not write to operational users, bookings, services, or transactions. Review the script and target database configuration before using that option.

## Interpretation limits

- The date span is a generated sample span, not evidence that the salon operated or recorded transactions on those dates.
- The fixed seed makes the output reproducible, not statistically representative.
- Transaction frequency, branch allocation, service mix, prices, discounts, payment methods, and commissions are assumptions encoded in the generator.
- The sample has only completed transactions. It cannot support analysis of cancellations, no-shows, refunds, or actual appointment conversion.
- Prices use the current service list because no verified historical price list was supplied; they should not be treated as historical prices.
- The importer converts each transaction into one service item and treats its date as a completed booking date for the synthetic forecasting tables. Forecasts based on this data describe the synthetic sample only.
- Names such as `Synthetic Customer 000001` are placeholders and must not be merged with real customer identities.

For schema and workflow details of the operational demand forecast, see [`../AI_FORECASTING.md`](../AI_FORECASTING.md). That workflow uses live operational booking data and is separate from this synthetic transaction dataset.
